# Security Audit — 2026-09-06

> Initial audit of the first production-ready version of the web app.

## Scope

- All source under `src/`
- `next.config.mjs`, `package.json`, `package-lock.json`
- Auth, routing, headers, dependencies

## Method

- `npm audit` (dependencies)
- Manual review of auth flow, headers, CSP
- grep for forbidden patterns (`eval`, `dangerouslySetInnerHTML`, secrets)
- Cross-check against OWASP Top 10 (2021)
- Review of the four legal pages against Razorpay onboarding requirements

## Findings

### Resolved in this audit

| # | Finding | Severity | Fix |
|---|---|---|---|
| 1 | No security headers in `next.config.mjs` | High | Added HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, COOP, COEP, CORP, X-Permitted-Cross-Domain-Policies. See `next.config.mjs`. |
| 2 | `next.config.mjs` exposed `reactStrictMode` only | Low | Added explicit `poweredByHeader: false` and headers() block. |
| 3 | No CSP nonces; relied on `'unsafe-inline'` | Medium | Documented; long-term plan in `HEADERS.md`. |
| 4 | Auth mock in `localStorage` with no clear "demo only" notice | Medium | Added banner + comment in `src/lib/auth.tsx` and README. |
| 5 | External links to Razorpay without `rel="noopener noreferrer"` | Low | N/A — we use the SDK in a script tag, not a plain anchor. Documented. |
| 6 | No CONTRIBUTING / SECURITY.md at repo root | Medium | Created `.agents/` and `security/`. |
| 7 | No CSP, Permissions-Policy docs | Low | Created `security/HEADERS.md`. |
| 8 | No threat model | Medium | Created `security/THREAT-MODEL.md`. |
| 9 | No incident response plan | Medium | Created `security/INCIDENT-RESPONSE.md`. |
| 10 | No pre-release checklist | Medium | Created `security/CHECKLIST.md`. |
| 11 | No formal security policy | High | Created `security/POLICY.md`. |
| 12 | No data classification | Medium | Created `security/DATA.md`. |
| 13 | No dependency / supply-chain policy | Medium | Created `security/DEPENDENCIES.md`. |
| 14 | No auth model document | Medium | Created `security/AUTH.md`. |
| 15 | Forms in `login` and `signup` used raw `console.log` paths via dev hot-reload only | Low | Cleaned. No `console.log` in shipped code. |
| 16 | No OG image, no `robots.txt` | Low | Created `public/robots.txt` and `public/og.svg` in this PR. |
| 17 | No `Sitemap.xml` | Low | Created `app/sitemap.ts` (dynamic). |
| 18 | Search forms had no debounce / rate limit | Low | Client-side debounce added. Backend rate limit documented in `AUTH.md`. |

### Residual / accepted risks

| # | Risk | Reason | Owner |
|---|---|---|---|
| R1 | No real backend; auth is mocked | Pre-launch phase, documented in README | Tech lead |
| R2 | CSP uses `'unsafe-inline'` for scripts | Next.js hydration requirement; nonce plan in `HEADERS.md` | Frontend |
| R3 | Razorpay checkout is loaded in a frame; relies on Razorpay's CSP | Industry standard; razorpay.com is allowlisted | Payments |
| R4 | Some pre-existing data (e.g. `console.warn` in dev) | Will be re-checked in next audit | Frontend |
| R5 | Next.js 14.2.35 has known DoS / SSRF advisories with no patch in the 14.x line (fixed in 15.5+) | Upgrading to 15.x is a breaking change requiring migration. Plan upgrade in next sprint. None of the affected code paths (image optimizer remotePatterns, beforeInteractive scripts, Pages Router i18n, custom server SSRFs) are used by this app — App Router, no custom server, no remotePatterns, no Middleware. **Effective risk: low.** | Tech lead |
